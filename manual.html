1 · What it is

A Waveshare ESP32-S3 with a 1.54-inch e-paper screen, a microphone, a speaker and an SD card slot, running firmware written for this project. You press a button, say something, and press again. The recording lands on the card as a plain .wav file with a plain .txt transcript beside it.

Everything is a normal file on a normal FAT32 card. If the firmware, this manual and every server involved disappeared tomorrow, you could still put the card in a laptop and read your notes. That is the point.

Three things are optional Transcription needs a server you run. Reading notes away from home needs a GitHub repo you own. Running unplugged needs a battery. The device records, plays back, tags and shows notes with none of them.

2 · What you need

ThingDetail
The boardWaveshare ESP32-S3 1.54inch e-Paper AIoT board, 200×200, black/white. Non-touch. The firmware is built for two buttons.
microSD cardFormatted FAT32. Any size; 8–32 GB is sensible. It must be in the device before power-on.
USB-C cableA data cable. Charge-only cables power the board but never appear on the computer, which looks exactly like a dead board.
Battery (optional)3.7 V LiPo with an MX1.25 2-pin plug. Most cells ship with JST-PH 2.0 mm, which does not fit.

3 · First setup

  1. Format the card as FAT32 and put it in the device while it is off. The device creates /recordings and /www itself on first boot.
  2. Copy the web page onto the card at /www/index.html. Get it from the repo. Without it the device falls back to a plain built-in page.
  3. Power it up over USB.
  4. The tour runs — 17 screens covering every feature. Press either button to move on, or double-tap to skip; it will not ask again. Settings → Extra → Redo tutorial brings it back.
The clock The device has no idea what time it is until something tells it. Open its web page once and your browser sets the clock automatically — that goes into a battery-backed clock chip and survives being switched off. Until then, notes are named rec_noclock_… instead of a date.

4 · The two buttons

There is no touchscreen. Everything is two buttons.

GestureWhat it does
TOP tapMove the highlight to the next option
TOP hold ≈1sChoose the highlighted option
TOP double-tapGo back
BOTTOM tapStart/stop recording — and play/stop a note when you are looking at one
BOTTOM holdScroll down a long list
BOTTOM hold 5sPower off — see the warning below
The bottom button is not a normal button On this board the PWR button is wired to a power-path controller, not to the processor. Software cannot see it at all. Holding it switches the device off in hardware, and that only works when running on battery — you cannot cut power that a USB cable is still supplying. The firmware's own power-off is on the top button instead.

The highlighted row is drawn as a solid black bar with the label reversed out. That is the thing a hold will choose.

5 · Making a note

Tap the bottom button. It works straight from the menu — catching a thought is one press, not four. A filled circle appears while it records.

Tap it again to stop. A square appears, then the tag picker.

Notes stop by themselves at two minutes. Audio is 16 kHz mono, roughly 1.9 MB per minute.

Why a circle and not a timer E-paper redraws by inverting the whole panel, which takes about two seconds and wears the display. A running clock would repaint hundreds of times per note to tell you something already written into the file. The circle is drawn once, the square once, and nothing in between.

6 · Tags

Five, fixed: Work, Projects, Ideas, Quotes, Random. The picker appears the moment a recording saves. Tap to move, hold to choose, or pick SKIP.

A tag is a file: rec_20260901_103045.tag containing one word. Re-tag any time from the note list on the device, or from the web page.

7 · Playing a note back

VIEW NOTES → pick a tag → tap the bottom button. That plays the highlighted note without opening it. Tap again to stop.

Holding the top button opens the note instead, showing its transcript, with PLAY and DELETE inside. Delete asks twice and removes the audio, transcript and tag together.

8 · The to-do list

A checklist kept as /todo.txt in plain text. Hold the top button on a row to tick it off. Add and edit items from the web page, or by editing the file directly — [ ] and [x] are all the syntax there is.

9 · Wi-Fi

Two ways in:

  • Settings → Wi-Fi starts a hotspot from the device called MonoNote-XXXX, key record123. Join it and browse to 192.168.4.1.
  • Settings → IP joins the network already configured and shows the address it was given.

Joining a network also sets the clock from NTP, which is written into the clock chip so it survives a power cut.

10 · The device's web page

With the device on your network, open the address from Settings → IP in any browser. Log in with admin and the device password (record123 unless you changed it).

You get search, tag filters with counts, audio playback, transcripts, re-tagging, deletion, the to-do list, and every setting.

Change the device password It is record123 out of the box and that default is published in a public repository. It is the only thing standing between your notes and everyone else on your network. Settings → Device password.

This page is served by the device itself from the SD card. It needs no internet at all — which is the point, since it works on a network with no route out.

11 · Transcription

Optional, and it runs on your own machine. The repo ships a server in server/ using Whisper on your GPU and Ollama for the rest — nothing leaves your network.

  1. Run server/run.ps1 on your PC.
  2. Find that PC's LAN address (ipconfig).
  3. Put http://THAT-ADDRESS:8000 into the device's API base setting.
  4. Allow port 8000 through the firewall.

Press Sync. Every clip without a transcript is uploaded, and the text comes back as a .txt beside it. Leave the field blank and sync skips this half without complaining.

12 · Reading your notes anywhere

Sync can also push notes to a GitHub repo you own, which the web app reads from anywhere.

Make the repo

github.com/new — any name, Private, no README. The device creates the file itself.

Private, not public A public repo means anyone on the internet can read every transcript. Private costs you one extra step: the web app needs a token to read it too.

Make a token

github.com/settings/personal-access-tokens/new — it is buried at the very bottom of GitHub's settings sidebar under Developer settings, so use the direct link.

  • Repository access → Only select repositories → your notes repo
  • Permissions → Repository permissions → Contents: Read and write. Nothing else.
  • Copy it immediately — GitHub shows it once.

That scoping is what makes this acceptable: the token sits on the device in plain text, which is unavoidable if the device is to push on its own. Scoped this way, a lost device means someone could write to one notes repo, not touch your account.

Put it on the device

Web page → Settings → Publish to your repo: owner, repo, token. The page also shows your device ID, like mnm-1dd81ab0. Write it down.

Read them

https://atreyap31-cell.github.io/mono-note-mini/?o=OWNER&r=REPO&d=mnm-xxxxxxxx

Same site for everyone; the link decides whose notes load, and it is remembered after the first visit. Each device writes one file of its own, so several can share a repo without overwriting each other.

Text only GitHub's contents API refuses to read back anything over 1 MB, and base64 audio crosses that within a few clips — at which point the file stops being readable by the app meant to display it. Audio stays on the card, reachable over your own network.

13 · Battery

Optional. Without one the device runs only while USB supplies power, and stops the instant you unplug it — with the last image still on the glass, which looks alarmingly like a crash.

  • Connector: MX1.25, 1.25 mm pitch. Most LiPo cells ship with JST-PH at 2.0 mm, which is visibly chunkier and will not fit.
  • Check polarity before plugging anything in. Probe from a ground point (the USB shell) to each battery pin with a multimeter on continuity: the pin that beeps is negative. Reversed polarity destroys the board and possibly the cell, and unlike everything else here it is not recoverable.
  • The board charges the cell over USB.
  • The gauge reads in quarters, using the chip's factory-calibrated ADC.

Getting to the connector means opening the case. Take the SD card out first, work on a hard surface, touch something earthed, and treat the e-paper's ribbon cable as the one part that will not forgive you.

15 · When something is wrong

The screen never changes, no matter what

E-paper keeps its last image with no power at all, so a frozen picture is indistinguishable from a working one. Check whether it is actually running before assuming the software is stuck.

Nothing responds and the screen is frozen

Most likely the chip is sitting in its ROM bootloader, which happens on every reset while GPIO 0 is held low — a stuck BOOT button will do it. The firmware never starts. Confusingly, flashing still succeeds, because the bootloader is exactly what flashing talks to.

A successful flash is not evidence that any code is running This one cost most of a day. Make sure no button is held or jammed, then unplug and replug with nothing pressed.

The computer does not see the device

  • Charge-only cable — by far the most common cause. The board powers on and never enumerates.
  • It went to sleep. Press a button. On USB it stays awake, but only if it booted with the cable already attached.
  • The port is wedged. Unplug, hold the top button, plug in while holding, release after 2 seconds. That forces ROM download mode, which uses a separate USB stack.
  • Try a different USB port, ideally straight into the machine.

Playback does nothing

Make sure you are pressing the bottom button. If the row shows X and a reason, that names the fault directly.

Notes are called rec_noclock_…

The device does not know the time. Open its web page once, or connect it to Wi-Fi.

Sync fails

The device shows GitHub's own error message. 401 means the token is wrong or expired; 404 usually means the owner or repo name is wrong, or the token is not scoped to that repo.

16 · Flashing and recovery

cd firmware
.\flash.ps1              # build, upload, then open the serial monitor
.\flash.ps1 -Build       # build only
.\flash.ps1 -Monitor     # just watch the serial output

If the upload fails it is nearly always one of three things, in this order: a charge-only cable, needing the top button held while it connects, or another program holding the port.

Going back to a known-good state

Tagged milestones in the repo carry the exact binaries that were running when everything worked. Restoring flashes those directly, so it does not depend on the source still building. The SD card and your saved settings are left alone.

17 · Hardware reference

Each of these contradicts the board's own header file, and each was established by measuring rather than reading.

FactWhy it matters
8 MB flash, not 16A 16 MB partition table overruns the chip and boot-loops the device
No touch controllerThis is the non-touch variant; nothing answers at 0x38 on any pin
PWR is not a GPIOWired to a power-path controller. Invisible to software on every pin.
GPIO 0 is the only readable buttonEverything the firmware reacts to comes from it
Battery ADC on GPIO 4, ÷2 dividerConfirmed against Waveshare's own example code
RTC PCF85063 at 0x51Battery-backed; keeps time across power loss
Temp/humidity SHTC3 at 0x70Present, currently unused by this firmware
Codec ES8311 at 0x18Microphone and speaker, 16 kHz mono
